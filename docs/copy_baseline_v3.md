# 第二阶段：文案基线 v3 与预留集运行

2026-09-23。本轮完成来源约束、否定属性/多SKU规则、冻结配置、开发回归及90件预留商品的单次文案运行。模型仍是本地Ollama的 `qwen3.5:4b-q4_K_M`，没有微调、RAG或第三阶段开发。质量验收仍需真实人工评分；下面的规则数字不能解释为准确率。

## 本轮实现

`copy_policy.py` 将来源区分为明确的单值属性、需要限定适用范围的可选值、无法确认含义的多值字段和明确否定事实。没有把所有多值字段都认定为合法SKU，也没有推断不同字段的笛卡尔积组合。

- “是否有童锁：否”不能变成“配备童锁功能（无）”；“有帽不可拆”不能变成“可拆帽”。允许省略该属性，禁止反向表达。一般“是否…”字段采用有限的词法规则，不覆盖所有自然语言否定方式。
- 引用多值内存、颜色、年龄等时检查同一分句中的选项限定；检查同一分句拼接多个数值选项的未确认组合。无法判断时保留为待审核，不自动选择某个SKU。
- 型号等含糊多值字段进入省略清单；若另一个明确单值字段独立支持相同事实，规则不会仅因词面相同而误报。
- 品牌为other/其他而标题出现疑似英文名称时，标为潜在来源冲突；屏幕尺寸与颜色/规格字段中的尺寸不一致、是/否互相矛盾时，也暂停生成。英文名称不必然是品牌，所以前一种是保守风险标记，须人工确认，不能宣称已经识别出真实品牌错误。
- 保留数字、单位、区间、无依据功效等检查，增加详情100字长度检查，修复百分比与身高的数字误匹配、明确“非”字否定、已有区间空格变化等误报。
- 来源冲突时不调用生成模型；规则标记的生成结果完整保留，状态为 `blocked_by_rules`。未触发规则的状态为 `draft_requires_human_review`，不是可直接发布的“已验证正确”结果。

提示词只控制基线行为，不能确保所有生成事实正确。规则也有误报和漏报，例如单位同义表达、中文数字、拆分句子后的SKU关联、来源本身错误及未列入词表的功效描述。因此没有根据规则标记自动重试并挑选更好结果。

对300件冻结商品运行同一来源策略，296件可带约束进入生成，4件触发疑似品牌/标题风险；共有172个含糊多值字段发现，数量单位是字段发现而非商品数。完整记录在 `artifacts/source_policy_v3_audit.json`。这不是人工审核完成或数据全部无冲突的证明。

## 90件预留集结果

运行目录 `artifacts/copy_v3_heldout_001/`。从原始test对应的项目heldout集中按固定hash优先级选择三个品类各30件，共90件；不根据生成结果补样、换样或重试。

| 项目 | 数值 | 含义 |
|---|---:|---|
| 预选样本 | 90 | 三品类各30 |
| 完成三类文案生成 | 89 | 标题、详情、3条卖点均有完整结构 |
| 来源风险暂停 | 1 | 未发送该商品的生成请求 |
| 生成失败 | 0 | 本轮无其他生成错误 |
| 输出有规则标记 | 42 | 含真实风险和可能误报，需人工判断 |
| 未触发规则的草稿 | 47 | 仍需人工审核，不等于47件事实正确 |
| 生成覆盖率 | 89/90，98.89% | 工程产出覆盖，非质量分数 |

发生的规则发现按条计数：无依据数字/单位21、含糊来源字段复用18、无依据词项34、可选值写成固定值6、详情超长4、新区间13、否定属性未保留1。一件商品可同时触发多个规则，不能将发现数相加当作问题商品数，也不能据此直接计算事实错误率。

性能：显式预热后顺序运行，89件有输出商品包含检查的耗时P50为1.921秒，P95为2.615秒，最大9.620秒；89次均≤10秒。预热响应单独保存，来源暂停与失败不混入成功请求分布。该结果不含服务启动、不等于并发压力测试或长期SLA。

运行尾段GPU快照：RTX3070 Laptop总显存8192MiB，整卡已用5756MiB、可用2263MiB；驱动报告数值不要求严格相加等于总量。这是单时点整卡快照，**不是模型独占占用或峰值显存**。Ollama驻留记录见 `artifacts/copy_v3_runtime.json`。

本轮预留结果产生后，没有依据其成绩继续修改冻结代码。后续若据这些样本调优，应将其视为已使用评测集，并另选未参与调试的最终测试样本。
