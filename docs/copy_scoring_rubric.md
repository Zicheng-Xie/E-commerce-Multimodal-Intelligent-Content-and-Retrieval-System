# 第二阶段文案人工评分规则 v1

本规则配合冻结文案运行使用。评价单位为一件商品的完整输出（标题、详情、3条卖点），不是单独一句话。评审人先对照来源独立阅读，再参考自动规则，避免把规则标记直接当答案。规则应在评分前固定；有分歧的样本保留备注，建议第二位评审复核，不凭模型自评分代替独立人工判断。

## 评分字段

`relevance_pass`：三类输出围绕同一正确商品类型，关键属性与来源一致，型号、数字、单位、否定关系及SKU适用范围无实质错误；没有无依据功效、认证或促销。如果来源有明确核心参数（如手机内存、尺寸、材质），输出不应只剩品牌和“以实物为准”等空泛措辞，省略导致核心信息不足也判不通过。多个SKU可通过明确提示规格按所选款式核对处理，不能拼凑未经确认的组合。三个字段中任一存在实质偏差，整条为false。

`fluency_pass`：标题可读，详情和三条卖点为自然、通顺的简体中文；无截断、明显语病、自相矛盾、无法理解的字段堆砌或不必要的重复。不因轻微空格差异单独判失败。三个字段任一存在影响理解的问题，整条为false。

`factual_error`：存在至少一处与允许使用的来源矛盾或来源无法支持的客观陈述时为true。遗漏本身不计事实错误，但可能导致相关度不通过。真实性仅相对于提供的数据，不能证明商家的原始声明真实。

`reviewer`：真实评审人的姓名或稳定代号，必填。不得冒用评审人、填写虚构的人工结果。

`note`：不通过或有事实错误时记录位置、原文、来源依据及原因；无法判断时先保留评分null并说明，不允许把null视为false。

## 阻断、失败与分母

- `draft_requires_human_review` 与 `blocked_by_rules` 都有真实模型输出，均需要人工评价，不能只挑规则通过的样本。
- `blocked_source_conflict` 与 `generation_failed` 没有可评分的完整文案，三个评分字段保留null；评审人确认原因并填写reviewer和note。
- 分别报告“实际生成输出的人工通过率”和“全部预先选定样本的通过率”。后者把阻断/失败视为未完成，不让拒绝生成带来虚假的高通过率。
- 事实错误率仅对有输出且已人工评分的样本计算，同时报告生成覆盖率和阻断数量。

PDF中的相关度≥80%、通顺度≥85%在这里操作化为上述商品级二元人工通过率。这是本项目明确选择的评分实现；PDF没有提供逐项评分表，不能把该实现冒充原文规定的唯一算法。评审规则与分母必须和最终成绩一起提供。

## 操作

1. 阅读运行目录的 `run.json`，确认角色heldout、模型、冻结版本、选中ID及来源数据哈希。
2. 将 `human_scores.template.jsonl` 复制为运行目录之外的 `artifacts/copy_v3_scores.reviewed.jsonl`，保留模板原样。
3. 对照复核HTML及 `records/` 中来源和模型结果，逐条填写布尔值true/false、评审人及备注。不要修改记录ID或状态。
4. 所有生成样本完成评分后运行：

```powershell
.\.venv312\Scripts\python.exe scripts\copy_baseline.py score --run-dir artifacts\copy_v3_heldout_001 --judgments artifacts\copy_v3_scores.reviewed.jsonl --output artifacts\copy_v3_quality_scores.json
```

空评分、缺失ID、重复ID、篡改的运行文件或为不存在的输出编造分数都会导致拒绝评分。

## 范围

本轮只做第二阶段的Prompt、来源处理、基线运行与基础评测。没有训练模型，没有引入商品知识库/RAG，没有开展第三阶段算法优化。查看预留结果后若继续改动提示词或规则，该批样本应作为已使用评测样本留档；新的最终评测应另用未参与修改的样本。
