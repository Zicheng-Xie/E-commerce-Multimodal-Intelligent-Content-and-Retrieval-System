# 电商多模态项目当前进度与后续安排

## 可直接用于汇报的说明

目前已建立本地Python与GPU环境，跑通千问文本、图片理解和结构化文案接口，并完成图文检索基线。下一步先统一团队环境，补齐阶段一整体方案和分析报告；随后围绕数据与评测、文案生成、图文检索三个工作包分工推进阶段二。当前重点是补齐修订后的明确品类数据、冻结新实验版本，并完成真实人工标注和质量评分。

## 环境同步的当前阻碍

本次实际检查确认Python 3.12.3、CUDA PyTorch 2.8.0+cu128及8GB GPU可用，本地Ollama接口正常响应。不过服务为0.40.1，原文案冻结服务为0.34.1；同名生成模型列表还出现两个不同摘要，均不同于冻结摘要。

应先确认同名请求实际加载的模型和服务存储目录，再决定新实验统一配置。本次没有修改模型、冻结文件或历史推理结果，也没有重新测量模型质量。完整记录见 [本次环境快照](../artifacts/environment_handoff_20261010.json)。

## 三个工作包的分工建议

以下为待团队确认的任务分配，不表示成员已领取任务或作出工期承诺。

| 工作包 | 任务 | 交付与衔接 |
|---|---|---|
| 数据与评测 | 确认分类、补齐商品、去重和组隔离、保留官方split、冻结新数据；组织独立人工评分 | 数据清单与哈希、查询与正例规则、评分汇总；先提供统一数据给另两包 |
| 文案生成 | 核对当前模型；以合同v2运行新数据，保留来源、请求、输出、拦截原因；分析事实问题 | 独立命名的文案运行、评审模板、失败案例和配置；交由真实评审人评分 |
| 图文检索 | 对新数据构建索引，固定查询和候选池，冻结排序；记录性能及失败案例 | 新索引、完整预测、性能记录、检索评审包；标注完成后离线评分 |

三包先共用同一数据版本、模型配置和评测协议，再并行实施。评审人应先独立判断，再查看自动规则提示；使用过的开发案例不能再次作为未见测试样本。

## 下一步顺序与验收条件

1. **统一环境**：每台机器确认Python、CUDA、Ollama服务、生成模型摘要、嵌入revision及数据路径；记录新统一配置并完成一次真实加载验证。
2. **补齐阶段一材料**：团队确认整体技术方案，补齐商业或行业分析报告，形成完整阶段一汇报材料。
3. **冻结新的明确品类数据**：人工确认分类规则，按确定的样本方案补齐，保留去重、商品组隔离、来源和哈希，并另留独立测试样本。
4. **运行新版本基线**：文案采用合同v2；检索建立匹配数据版本的新索引，冻结全部预测。新目录保存，不覆盖旧结果。
5. **完成独立质量评审**：逐项填写真实文案评分与完整候选相关性，处理歧义；合并后计算正式指标及对应分母。
6. **提交阶段二四项交付物**：标准化多模态数据集、中文文案基线、图文检索基线、正式基线效果报告。根据正式结果再决定后续优化方向。
