# 导师建议对应的第二阶段工程调整

本轮采用与现有文案生成、图文检索和基础评测直接相关的建议。保留原300件商品冻结集及90件真实预留文案结果，新增专项开发验证集。第三阶段微调、RAG、对比学习，以及后续分割推理、局部定位、服饰问答均未开发。

## 样本数量怎样选择

“20–30条”适合作为第一轮发现明显问题的初测规模，不是正式评测上限。增加**独立、覆盖合理、标签可信的评测样本**主要缩小估计误差，并不会自动改变模型参数或提高真实准确率。重复商品、同一商品的多张近似图片不能简单当作独立样本；图库数量和查询数量也必须分别报告。图库扩大可能因干扰商品增加而使检索更难。

以观察通过率均为80%为例，Wilson 95%区间如下，仅用于说明样本量影响，**不是本项目质量成绩**：

| 独立评价数 | 观察通过率 | 95%区间 |
|---:|---:|---:|
| 30 | 80% | 62.7%–90.5% |
| 90 | 80% | 70.6%–87.0% |
| 300 | 80% | 75.1%–84.1% |

因此保留90件三品类真实商品评测，再补30个合成边界输入；两种数据不能合并为“120件独立真实商品准确率”。检索新增千张图库，也不能称为“1000次有标签查询”。区间方法参考 [NIST比例置信区间](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)；调参时隔离评测数据参考 [scikit-learn数据泄漏说明](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)。

## 采用范围与实现

| 建议 | 本轮实现 | 解释边界 |
|---|---|---|
| 图片搜图片 | 保留真实商品主图查询CLI，新增服饰整图同款找回量化实验 | 同款与广义相似款分别定义；消费者照片到商品图的成绩不代表商品主图到相似款成绩 |
| 完整相关标注、Recall@10、Precision@10 | 使用原始配对标签生成固定候选池内全部同款正例，覆盖5类服饰 | 300件商品的跨品类、广义相似款相关性仍需完整人工复核 |
| 颜色相似、品类不同的负例 | 按原标注类别找跨类负例，用原始衣物多边形内亮度筛选深色负例，记录排在首个正例前的情况 | 不将整幅背景颜色当服装颜色；该统计不能单独证明模型“只看颜色” |
| 百级、千级耗时 | 100/300/1000张真实图的嵌套图库；图片、文本向量生成和已加载索引检索分别计时 | 顺序预热调用，不是并发压测；记录模型加载及显存峰值 |
| 分数分布、阈值 | 分开统计文搜图、图搜图、同款正负例原始余弦分布 | 已有L2归一化；不把余弦当概率，不在当前评测数据上拟合阈值 |
| 事实与营销分开 | 新增 `content_contract.py`，事实草稿和允许的营销语句使用独立字段；沿用来源、否定、多SKU和事实规则 | 原始属性才是参数来源，LLM草稿不成为新事实；规则无告警仍需人工复核 |
| 属性缺失、来源冲突 | 可选未知参数不补全；名称、品类或全部属性缺失时停止生成；空白值按缺失处理；事实冲突继续阻断 | 不默填材质、尺寸、功能、品牌 |
| 品类与风格 | 三个大类的90件真实预留样本；另做3类×10情形；neutral/concise/friendly三种受控营销通道 | 当前风格使用允许的固定句，不宣称已经验证任意自由营销风格 |
| 问答不适用/模糊/遮挡/多主体/袖口局部问题 | 记录为后续阶段测试要求，未新增问答或局部推理实现 | 读取已有分割标注做诊断不等于开发分割模型 |

## 工程结构

`content_contract.generate_content()` 对输入做缺失处理，再调用原v3生成器；输出 `source`、`factual_copy`、`marketing_line` 和明确状态。来源暂停及规则拦截时不返回营销语句。所有生成结果仍是草稿，不能因自动规则通过就当作“事实一致性100%”。本轮没有改动冻结的 `copy_policy.py`、`fact_check.py`、`ollama_client.py`、`copy_experiment.py`，旧90件结果继续对应原配置。

`retrieval_benchmark.py` 负责数据校验、实验协议、模型调用、分项性能记录、同款指标及负例审计；`measurement.py` 统一分位数、Wilson区间和按商品组重采样的探索性区间。评测代码不修改检索排序，当前仍使用整图2048维向量和原始余弦；品类标签只用于划分实验和分析结果，不注入查询、不参与过滤或加分。

## 新增数据与同款标签

`data/mentor_fashion_1000_v1/` 从原始train/validation各复制前500张图片及对应标注，共1000张图片、2000个带SHA256副本。此为确定性开发覆盖样本，并非随机总体抽样或新的独立测试集。

同款键是 `source_split/pair_id/style/category_id`，仅 `style>0` 可构成正例。来源定义参考 [DeepFashion2官方数据组织说明](https://github.com/switchablenorms/DeepFashion2#data-organization)。不同官方划分的同数字pair_id不合并。查询选单件服饰的user图、同一身份最多一个查询；候选池为shop图，排除与查询字节完全相同的图。全部原图送入模型，无框裁剪、局部分割或语言引导定位。

已冻结26个查询，覆盖短袖上衣6、背心裙6、长袖上衣5、短裤5、长裤4；候选池334张shop图。1000张是性能图库规模，334张是同款质量实验候选池规模。协议与全部正例在调用嵌入模型前写入 `protocol.json`，不能只给Top10标注后反算Recall。

这26个查询均来自源train：源validation前500张没有可与当前shop副本匹配的同划分正例。源train未用于本项目模型训练，但该开发样本仍不能称为官方验证集成绩。26个身份属于20个pair组，同组身份的相关性已在区间估计中保留。1000张图片SHA256均不同；这不等于1000个不同商品，也未排除所有近似图片。

`Precision@10=前10项正例数/10`；`Recall@10=前10项正例数/该候选池全部正例数`。每个查询正例通常很少，因此另报告Precision@10可达上限，不能拿这个严格同款任务的Precision与广义相似款阈值直接比较。查询按源split/pair_id分组bootstrap，区间仅作探索性说明。

## 检索与性能实测

原始结果：`artifacts/mentor_retrieval_v1/report.json`，逐查询结果 `query_metrics.json`，负例 `hard_negatives.json`，完整协议 `protocol.json`，复核页 `same_item_results.html`。

| 同款指标 | 本轮数值 | 20个源pair组bootstrap探索性95%区间 |
|---|---:|---:|
| Recall@10，按查询宏平均 | 78.12% | 66.51%–87.34% |
| Precision@10，按查询宏平均 | 35.77% | 25.66%–50.50% |
| 此候选池Precision@10平均可达上限 | 47.69% | 各查询正例数量决定，无区间 |

| 服饰子类 | 查询数 | Recall@10 | Precision@10 |
|---|---:|---:|---:|
| 短袖上衣 | 6 | 65.48% | 43.33% |
| 背心裙 | 6 | 81.94% | 15.00% |
| 长袖上衣 | 5 | 84.33% | 48.00% |
| 短裤 | 5 | 70.00% | 28.00% |
| 长裤 | 4 | 93.75% | 50.00% |

这些子类样本很少，适合定位问题，不适合声称品类间存在稳定显著差异。指标使用所有正例计数，**不是至少命中一个商品的Hit@10**。

260个Top10位置中50个为类别完全不重叠的商品图，占19.23%。例如查询 `deepfashion/train/000197`（短袖上衣）的第一正例在第10位，第一位却为 `deepfashion/train/000192`（长袖上衣+长裤），图像余弦约0.4976。因此尚不能宣称品类混淆已解决。

8个深色查询存在深色跨类负例，其中没有负例排在首个同款正例前（0/8）；这只是很小的诊断样本，不证明不存在“只看颜色”问题。深色定义为已有服饰标注区域内超过一半像素灰度小于70；多主体图不计算该颜色诊断。原始多边形仅用于诊断掩码，极少数越界坐标由栅格边界裁切，原标注文件未改写。

耗时：RTX3070 Laptop、BF16、batch=1。每种模态10个固定输入，重复5次，分别50次；向量编码只执行一次，再送入三个图库，不把同一编码重复算成150个独立测量。预热后的外层编码耗时包含读取图片、预处理、GPU执行和结果回传；已加载索引耗时包含匹配、排序和结果组装。总耗时为该次编码与对应图库检索之和，不含模型/磁盘索引加载或网络服务。

| 操作 | P50 | P95 |
|---|---:|---:|
| 单条文本向量 | 38.43 ms | 49.44 ms |
| 单张图片向量 | 131.90 ms | 145.57 ms |
| 100图库检索，文本/图片查询 | 0.30 / 0.28 ms | 0.34 / 0.32 ms |
| 300图库检索，文本/图片查询 | 1.23 / 1.19 ms | 1.79 / 1.80 ms |
| 1000图库检索，文本/图片查询 | 1.92 / 1.87 ms | 2.41 / 2.37 ms |
| 1000图库编码+检索，文本 | 40.26 ms | 51.62 ms |
| 1000图库编码+检索，图片 | 134.04 ms | 147.57 ms |

模型加载5.58秒，PyTorch峰值分配4118.84MiB、峰值保留4134MiB。这不是整张显卡总占用。千张图库真实向量无复制扩容；索引附带的文本向量是类别名，仅为复用索引结构，匹配目标始终为图片向量，不能将其解释为商品标题检索质量实验。

同款正例余弦P05/P50/P95为0.315/0.476/0.660，负例为0.056/0.189/0.372，分布存在重叠（正例最低0.150、负例最高0.670）。因此本轮不引入统一“相似度≥0.5”之类门槛。无标注文搜图P50为0.155、图搜图P50为0.196，二者也不能直接当同一置信度刻度。无标注图搜图分布包含性能查询自身，只用于数值诊断；同款质量指标已经排除自身/同字节图。后续如需要拒识阈值，应在独立开发相关性标注上按业务误召回/漏召回成本校准，再在未参与调整的数据上报告效果。

## 文案边界实测

结果在 `artifacts/mentor_copy_boundary_v1/`：30个明确标识为合成的场景，覆盖三类商品的完整输入、缺品牌、缺材质、缺尺寸、缺功能、全属性缺失、名称缺失、品类缺失、布尔冲突、多SKU。

| 结果 | 数量 |
|---|---:|
| 缺必填信息，未调用生成 | 9 |
| 来源事实冲突，生成前阻断 | 3 |
| 有完整生成输出 | 18 |
| 其中被输出规则拦截 | 5 |
| 其中进入待人工复核的草稿 | 13 |

12个确定性前置边界按预期停止。缺品牌/材质/尺寸的指定词项扫描未发现补写信号，但这只是有限词项扫描，不是完整语义证明；文案相关度、通顺度的人工通过率仍为空。

有明确失败证据：模型把输入“棉”扩写成“纯棉”，规则已捕获。也有可能误报：如“提供10厘米和20厘米两种尺寸”被多SKU规则标记，需结合上下文人工判定。5条被拦截不能等同于5条事实错误，13条未拦截也不能等同于全部事实正确。保留失败原文及来源，不以换样或重试隐藏问题。

## 运行入口

以下命令从工程根目录执行。已有数据和结果不必重跑；重新实验需要新的输出目录。两个模型顺序使用GPU，检索脚本仅卸载本项目生成用千问后加载嵌入模型。

```powershell
# 新副本和新实验目录示例
.\.venv312\Scripts\python.exe scripts\prepare_retrieval_benchmark.py --output data\mentor_fashion_1000_v2
.\.venv312\Scripts\python.exe scripts\benchmark_copy_boundary.py --output artifacts\mentor_copy_boundary_v2
.\.venv312\Scripts\python.exe scripts\benchmark_retrieval.py --dataset data\mentor_fashion_1000_v2\samples.jsonl --output artifacts\mentor_retrieval_v2

# 单件商品：事实草稿与受控营销语句分开返回
.\.venv312\Scripts\python.exe scripts\generate_content.py --product configs\example_product.json --style friendly --output artifacts\content_contract_example.json

# 复核已完成v1结果的哈希、协议、向量、指标与边界行为，无需模型推理
.\.venv312\Scripts\python.exe scripts\verify_mentor.py
```

v1保存了完整正例协议、HTML中的全部Top10及每查询指标；校验器从原始带哈希HTML提取ID独立复算成绩，结果存入 `artifacts/mentor_verification.json`。后续运行同时直接导出机器可读的全部排序 `rankings.json`。当前代码额外保留去空白后同名字段的全部不同值，避免静默覆盖来源冲突；v1合成输入没有该类同名字段，已保存结果不受影响。HTML文件做路径和数据核对，未宣称浏览器视觉验收。
