# 模块二 FG-CLIP 2 独立方法对照实验

已单独实现并实跑 `fgclip2_local_fusion20`，原方法 `cross20` 保留。完整结果见[内部原方法与新方法对照表](../artifacts/module2_fgclip2_comparison/internal_comparison.ai.development.md)，逐查询变化见[命中与候选变化](../artifacts/module2_fgclip2_comparison/internal_query_changes.json)。

本轮是已曝光数据上的 AI 开发实验，没有新增独立验收成绩。新方法在部分图片查询上有收益，文本分支出现退步，整体未通过六指标不退化门槛，默认策略保持原版。Precision@10≥60%、Recall@10争取≥85%的正式目标继续保留，尚未完成新的独立验证。

## 新方法借鉴了什么

采用[FG-CLIP 2 官方仓库](https://github.com/360CVGroup/FG-CLIP)及[官方 Base 模型](https://huggingface.co/qihoo360/fg-clip2-base)的中英双语全局图文特征、密集区域特征和区域文本投影头，新增独立辅助分支。模型为完整383,803,394参数，固定 revision `430fbc8a912c86fd4de601381b6245a0edab22f0`，CUDA、float32、单样本推理，没有微调。

全局证据包含图图、图文及商品标题匹配；局部证据取查询区域描述与商品有效图像 patch 的相似度，使用最高5% patch的平均值。两者按全局75%、局部25%的排名权重融合。最终保留原先65%精排、35%召回的结构，将精排票重中的25%交给新增分支；原商品类型与属性偏移保持不变。

图片查询继续使用原来冻结的查询描述。描述缺失时停用描述与局部语义票，保留实际图片特征。全部文本按官方196/64 token上限处理，实际发生3次截断，原文本和token明细保留。图像采用官方按输入尺寸选择128至1024 patch的预处理规则，只移除padding特征。

该分支使用局部特征匹配；主体检测框和分割掩码属于后续可独立比较的策略，本轮实现及结果均不包含它们。

## 如何保证对照可比

- 开发组A、开发组B各16条查询、168件图库，另有8条已曝光图片查询使用A图库；两组图库共享72件商品。
- 40条查询、所有候选ID和6720条原AI关系保持不变。保留零正例和未知关系，没有新增或改动相关性判断。
- 原方法与两种融合方法使用同一20候选池、同一完整Qwen原始分数，完整返回168件商品；K固定为10。
- 原方法800对真实Qwen精排分数原样复用，逐查询重放与历史结果完全一致；本轮新增Qwen精排0对。
- 新方法、固定权重、对照方式和主方法名称先冻结，再生成预测；没有看结果后选择变体或改参数。
- 同时保留原整图、区域标题基线、新模型独立评分和全局分支消融，共6种方法、240组完整排序。独立FG评分覆盖全图库，其计算流程与融合方法分别说明。

对照表报告Precision@10、Recall@10、mAP、NDCG@10、MRR、Hit@1，并分总体、文本、图片查看。同一未决标签的所有可能取值用于配对差值计算；范围不是统计置信区间，也不包含AI判断误差。整体不退化门槛未通过，不能只摘取图片组中的较好结果发布。

## 根据本轮结果继续优化

图片分支值得继续研究，文本先沿用原方法。已观察到“耳机”查询将升级线配件提到整机前面的错误，后续需要加强主体与配件区分，不能单靠细粒度相似度。局部特征与主体ROI应分开消融，避免一次混入多个改动。

后续若按模态路由或改变候选分配，作为本轮结果启发的新方法另行冻结，不归入本轮预先定义结果。图库覆盖不足仍需单独建设；补库与排序收益分别报告。下一轮独立AI盲测必须在完整方法和评审协议冻结后使用全新查询与全新图库，本轮40条查询不能再次作为未见数据。
