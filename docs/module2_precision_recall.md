## 实验设计和真实负结果

新增策略包括多路RRF、公开主体证据的软调整、20/60件交叉编码精排以及各自叠加主体证据的版本。候选池用各路排名轮换去重补入，没有用源品类、相关性标签或查询ID挑候选。精排只读取原始查询、商品原图与原标题；图片查询的主体规则分支暂不猜类别，仍由视觉与精排比较主体。

所有权重和预算在本轮精排前固定：RRF常数60，交叉编码排名与召回排名按0.65/0.35融合，主体匹配加0.12、明确类型冲突减0.35、明确属性冲突减0.25、公开来源冲突减0.08。完整参数、输入文件与代码哈希保存在`protocol.json`。参数是开发候选，未获得真实质量验证。

扩大候选池带入了更多旧机器标记相关的条目：在旧159条机器正例中，20件池覆盖99条，60件池覆盖129条。这个计数不是Recall；机器正例既不完整，也存在错误。扩大精排并未稳定改善Top10，部分图片查询出现明显错排。例如一条置物架图片查询的60件精排，把家具连接件排到了最前。不能据此升级默认版本，也不能把机器一致性上下界写成Precision或Recall。

公开证据的软调整仍会把未识别类型商品推向尾部前列；配件或有线耳机也未完全排除。现有公开主体资料下，部分开发查询只有很少的明确支持项，例如短袖T恤1件、充电宝2件。这是素材覆盖不足的线索，**不是经过人工确认的正例数量或正式指标上限**。需要先补齐真实判断，再决定哪些商品类型应补充开发素材。

## 弱标签噪声的处理

59对冲突在本轮开发分析后选出，属于有针对性的开发诊断。复核只给本地视觉模型原图、原标题、原查询及开发相关性规则，不提示旧机器分数、主体冲突结果或期望答案。模型仍不能确定时，修订版本保留null，未当负例。

原5,143条记录及前轮判断均未覆盖。新版本保存旧判断、直接看图理由、原始响应、模型摘要、输入图片哈希与标签来源。修订后机器标签共120对相关、1,729对不相关、3,294对未知，仍全部是机器判断。20对被保留为相关也说明规则与机器可能互相矛盾，不能直接把59对规则冲突全部判为负例。

随后用同一分组训练配方重新拟合，不增加调参搜索：3个查询分组×3个商品族分组，留出图片查询的来源族也从训练两种角色中排除。逻辑回归与困难负例RankNet各训练9个分组模型，另各训练一个全机器已知标签候选。所有19种策略在同一修订标签版本上重新记录机器一致性；**标签版本变化不能当作模型质量增益**。

## 新的真实查询入口

新CLI接受任意项目内开发图片或新文本，每次重新编码，不按既有查询ID查表。必须显式选择开发候选；旧常驻服务和默认检索策略不变。

```powershell
.\.venv312\Scripts\python.exe scripts\retrieve_intent.py --text "无线蓝牙耳机" --method cross_pool20 --output artifacts/intent_text_001
.\.venv312\Scripts\python.exe scripts\retrieve_intent.py --image "项目内开发图片的完整路径" --roi 0.1 0.1 0.9 0.9 --method cleaned_logistic --output artifacts/intent_image_001
```

支持`multi_channel_rrf`、`public_evidence_soft`、`cross_pool20`、`cross_pool60`、`cleaned_logistic`和`cleaned_ranknet`。输出目录必须尚不存在，生成完整排序JSON及带商品原图/局部视图的HTML。排序分不代表正确率。查询图按原图字节及方向校正像素排除自身，预留验收图及其近重复在模型加载前拒绝；裁切保留原图的自身排除依据。

本轮实际运行：[文本精排结果](../artifacts/module2_precision_recall/demo_text/results.html)、[图片ROI与修订弱标签模型结果](../artifacts/module2_precision_recall/demo_image_roi/results.html)。两次均返回10个唯一商品。脚本内总耗时分别34.37秒、9.32秒，包含模型/索引加载，不含解释器启动和模块导入。文本精排顺序加载嵌入与精排模型以控制8GB显存，当前延迟不适合作为原快速入口的默认替代；这两次运行也不是正式性能验收。
