# 模块二：有限重排与新查询压力检查

更新：2026年10月23日。目标仍是Precision@10≥60%，Recall@10尽量≥85%。本轮已完成单一尾部策略比较、6张新来源查询的AI评审和完整模型实跑。正式验收尚未完成，独立heldout继续封存。

## 本轮做了什么

新增“前10位保留、尾部恢复原区域顺序”策略。图片先执行原查询描述、多视角、20候选图文联合精排及区域前两位保护，再保留其前10位，剩余商品按原区域基线相对顺序补全。文本分支沿用原固定策略。规则在比较前冻结，本阶段只比较这一项，不追加参数搜索。

旧18条查询新增18组完整排序，没有新推理或改标签。该规则保证P@10、R@10、NDCG@10、Hit@1与被保留的前10位一致，不能保证mAP和MRR改善。配对复核仍有不确定和回退，不升级默认策略。

## 为什么增加新查询

原18条查询经过多轮策略探索及针对性补库，继续在这些查询上调高数字不能证明泛化。本轮先冻结6个采样方向、训练来源窗口和种子，再从第1000001至1100000条抽18条元数据，每个方向选首张可解码、未重复的图片，共6张新查询。来源ID、商品族和原图指纹均与既有开发曝光及预留验收登记隔离。

采样词面出现实际主体漂移：键盘桶采到电钢琴，充电宝桶采到游戏/充电复合机，枕头桶包含枕套与枕体的歧义。全部保留，按可见实际主体评审，没有为了提高分数换图或删查询。网格生成曾误用旧输入字段，下载和登记已完成；原冻结脚本保留，单独finalizer核验并补齐网格，修复证据随本轮封存。

我直接查看6张查询图和418件图库的12页网格，先冻结2,508对AI判断，再运行模型；8对未知保留未知，来源明确为AI，没有冒充人工。图片判断仍要求主要主体/用途与可见外形相近，类别相同不足以判正。

新查询复用完整本地Qwen3-VL-Embedding-2B、Qwen3-VL-Reranker-2B和固定Qwen3.5查询描述，共实际执行6次查询描述、42次嵌入编码、120对图文精排。5种方法在同一图库上产生30组完整排序。既有完整模型、参数和查询预处理保持固定，没有按新结果回调参数。

这是一组包含无匹配和主体歧义情形的开发压力检查。图库已开发曝光，评审者也参与过旧开发评审，不能称为正式验收或独立标注验证。6条查询从本轮起全部进入开发曝光登记，今后不能再作为未见盲测。

## 当前结论

新检查同时发现图库匹配覆盖缺口与排序回退。已有商品不够相关时，重排无法生成真实正例；不能通过宽松标注、减少返回数、删除困难查询或限制Recall正例分母来追目标。

零正例查询仍保留在Precision等指标的总体分母，其Recall未定义；仅含未知的查询使用所有标签补全的精确范围。新旧比较在同一未知标签补全下计算配对差值。质量数值、容量审计和全部负结果仅存于[内部开发报告](../artifacts/module2_rank_stability/internal_report.md)，不对外作为成绩。

接下来优先补齐业务主体与可见外形的开发图库覆盖，再复验固定候选。正式heldout仍等待最终候选、输入处理和AI盲评协议冻结后进行一次验证；本轮验收推理0，正式指标为空。
