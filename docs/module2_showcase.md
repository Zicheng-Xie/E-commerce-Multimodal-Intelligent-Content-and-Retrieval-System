# 模块二商品检索演示平台

**2026-11-12 已回退到扩容前：** 当前只提供原 845 件电商商品的图搜、文搜和浏览。DeepFashion2 扩容已停用，启动入口也恢复为 `serve_showcase.py`。图片、向量及扩容源码保留在停用归档中，不会自动恢复扩容。

访问：**http://127.0.0.1:8766**。2026-11-10 已在这台 Mac 的 Chrome 新标签页打开，并实际完成文字检索、图片检索和上传验证。

## 展示范围

平台接入当前 **845 件商品的完整统一开发图库**，可分页浏览所有商品，查看原始主图、完整标题和商品编号。这不是原始阿里数据全集，也没有纳入封存验收商品。后台接受任意新文字需求或上传图片，不是仅播放历史 55 条查询的固定结果。

| 功能 | 操作 |
|---|---|
| 文搜 | 输入购物需求，点击“开始检索”或按 Enter；Shift+Enter 换行 |
| 图搜 | 切换“图片找商品”，上传或拖入图片；也可选择 36 张开发示例之一 |
| 商品浏览 | 点击左侧“商品图库”，分页查看全部 845 件商品 |
| 原图详情 | 点击商品卡片，放大查看原图、完整标题和编号 |
| 相似商品 | 在商品详情点击“用这张图检索”；同一原图对应的商品会排除自身 |
| 处理进度 | 展示识别、全图库检索、Top20 图文精排和实际耗时 |

上传支持 JPG、PNG、WebP，最大 8 MB、2000 万像素、单帧。请求只在本机服务和本机模型间处理。演示服务只监听 `127.0.0.1`，其他电脑不能直接使用这个地址；向上级展示可在本机打开或共享屏幕。

## 启动

下次双击项目根目录的 [启动商品检索平台.command](../启动商品检索平台.command)。服务已运行时直接打开页面；未运行时校验模型并启动。重启电脑后需重新启动，模型初始化期间等待终端打印就绪地址。Ollama 需保持运行，无需再下载模型。

也可在项目根目录运行：

```bash
.venv-mac/bin/python scripts/serve_showcase.py --open
```

当前已启动的服务在后台继续运行，进程信息保存在 `artifacts/module2_selected_runtime_20261110/showcase/server_process.json`，日志在同目录 `server.log`。正常前台启动时可用终端 Ctrl+C 停止。

## 实际模型和排序

复用来源与模型身份绑定的真实原图、主体图和标题向量，全部 845 件商品参与检索。运行时采用固定 Qwen3-VL-Embedding-2B、Qwen3-VL-Reranker-2B 和 Ollama `qwen3.5:4b-q4_K_M`；先描述图片主体，再编码召回，按既定策略构造 Top20、精排及保护／明确冲突规则。MPS 阶段串行释放，不同时常驻多个 PyTorch 模型。

调用原冻结的 `primary_public_conflict_matched_v1` 排序规则，没有把本轮尚未确认收益的类型约束实验切成默认。公开平台索引独立保存，不冒充原完整冷启动运行包或其质量验收。页面不读取人工 CSV 或相关性真值，不用查询身份查历史最终排序，不显示虚构价格、相关概率或未经独立验收的质量指标。

缓存绑定实际模型、提示词、实现、索引和输入内容，仅复用匹配的模型观察。界面第一次实际检索“无线蓝牙耳机”约 **37.07 秒**，游戏耳麦图片约 **65.01 秒**，均返回 10 件商品；相同输入再次查询可复用缓存。这是两个示例的工程实测，不代表生产延迟或检索质量达标。
