## 原始要求与验收

需求依据是 `Alibaba阿里算法实习/电商多模态智能内容与检索系统.pdf` 第2页模块二，第3页检索指标，第4页性能要求。用户2026年10月14日的新分工优先于该PDF的全项目阶段任务。

| 原始要求 | 当前实现与增强方向 |
|---|---|
| 图像与标题或描述进入统一向量空间 | 使用Qwen3-VL-Embedding-2B；整图、真实局部裁切和原标题分别编码 |
| 中文文本搜商品、图片搜商品 | 两条输入链路；图片可显式指定用户ROI，保留整图检索对照 |
| 相似度结合品类与属性综合排序 | 区域注意力、标题向量融合、用户明确的品类与属性偏好加减分 |
| Top-N与结果可视化 | 显示商品标题、主图、品类、分数、主要匹配视图及各项分数组成 |
| Recall@10≥70%、Precision@10≥60% | 在与实际商品相关性一致的标准化测试集上评价两种查询模式 |
| 单次检索≤5秒 | 分别记录模型加载、索引校验加载、查询编码、已加载索引匹配；最终Demo另测用户端完整响应 |

超过技术文档要求的目标是：更好地处理背景干扰、目标较小、多主体及局部细节查询，同时保留效果、性能和失败证据。正式成绩要与整图基线在同一测试集上比较，不能只根据增加策略数量判断完成。

## 本轮已实现的策略

| 策略 | 实现方式 | 实际作用与限制 |
|---|---|---|
| 整图保留 | 第一个向量直接编码原图；另存预览副本 | 保留已有模型预处理，防止裁切丢失主体整体信息 |
| 自动ROI候选 | 小图边缘颜色中位数估计背景，以像素对比提出包围区域并留边 | 仅为候选启发式；复杂背景、广告文字或多主体可能影响区域 |
| 中心裁切 | 取80%宽高中心区域 | 一种几何候选，不能视为正确商品框 |
| 重叠局部窗口 | 左上、右上、左下、右下各取65%宽高 | 保留跨窗口细节；无效或重复窗口去重 |
| 局部放大 | 真实裁切用Lanczos缩放到最长边768，再独立编码 | 增加局部在编码输入中的占比，不产生新的原始纹理信息 |
| 用户ROI | `--roi x1 y1 x2 y2`，坐标归一化并依据EXIF校正后的图像 | 用户选择关心区域，框必须在范围内且尺寸有效 |
| 区域注意力 | 查询向量对商品各视图做温度缩放余弦softmax | 根据当前查询动态加权区域，权重可查看 |
| 全局与局部融合 | 固定保留60%整图分数，其余由区域匹配提供 | 初始权重是工程预设；后续需在独立开发集校准 |
| 商品标题融合 | 视觉分数占80%、原标题匹配占20% | 只使用来源标题，不使用模块一生成文案 |
| 品类与属性排序 | 用户显式提供品类和字段要求；记录匹配、冲突、未知 | 缺失字段不伪造匹配；商品多SKU任一可选值命中不代表同一SKU组合成立 |
| 解释性结果卡片 | 主图、匹配裁切、区域权重、图文分数和条件依据 | 匹配分不是概率，视图权重不是目标定位准确率 |

商品索引每件最多7个视图，候选特征离线计算并缓存。查询编码完成后对全部候选区域精确匹配，当前百级至千级实验规模无需引入近似召回误差。

## 注意力实现

查询视图向量为Q，候选商品视图为K和V，全部向量先L2归一化。每个查询视图对该商品的视图执行：

```text
s_j = cosine(q, k_j)
a_j = softmax(s_j / 0.07)
z = sum_j(a_j * v_j)
regional_score = q dot z = sum_j(a_j * s_j)
```

对图片查询，整图查询视图保留60%区域聚合权重，多个局部查询视图共同占40%。最终视觉分数再按60%整图、40%区域分数融合。文本查询只有一个查询向量，直接对商品区域进行注意力匹配。

这是冻结嵌入上的查询引导交叉注意力，尚未训练Q/K/V投影或修改Qwen内部注意力层。实现使用NumPy显式计算并保存权重，便于复算和查看。[PyTorch注意力文档](https://docs.pytorch.org/docs/stable/generated/torch.nn.functional.scaled_dot_product_attention)描述了softmax加权值向量的一般机制。本实现使用归一化余弦与温度，而不是默认的维度平方根缩放。

[DELF原始论文](https://arxiv.org/abs/1612.06321)提供了局部特征与注意力用于图像检索的研究参考；本轮没有复现其网络或训练方法，也不把该论文的地标检索成绩当作电商效果依据。

## 排序与策略开关

| 开关 | 匹配逻辑 | 用途 |
|---|---|---|
| `global` | 原始整图查询与原始商品整图余弦 | 对照基线 |
| `mean` | 商品视图等权平均匹配，再与整图分数融合 | 判断单纯增加视图的作用 |
| `attention` | 查询引导区域softmax，加全局分支 | 验证注意力与局部视图组合 |
| `attention_fused` | 注意力视觉分数、原标题匹配、显式品类和属性偏好 | 产品综合排序入口 |

图片查询支持 `--query-views global`，仅编码查询整图后匹配商品区域；默认 `multi` 编码全部查询视图。显式 `--roi` 会在用户选定区域内生成多视图，不读取源标注框。

品类命中／不符分别加／减0.03；属性匹配数减冲突数，除以请求字段数后乘0.05。未知字段贡献为零。当前属性仅做来源字段的精确规范化匹配，不声称覆盖自然语言同义词、数值范围或SKU组合解析。

图搜商品不自动使用查询图的源类别或属性作为排序提示。同款开发实验的原始类别、pair_id、style只用于定义正例和评分，编码输入及排序数据中的类别与属性均为空。

## 运行与复现

在项目根目录的PowerShell运行。已有产物无需重复构建；新运行必须使用新目录名，避免覆盖历史证据。

```powershell
# 修订后的286件商品，真实裁切与原标题索引
.\.venv312\Scripts\python.exe scripts\retrieve_regions.py build --index data\index_regions_products_v1

# 文搜商品
.\.venv312\Scripts\python.exe scripts\retrieve_regions.py search --index data\index_regions_products_v1 --text "黑色马丁靴" --strategy attention_fused --output artifacts\my_region_text_001

# 图搜商品；以自己的图片路径替换示例路径
.\.venv312\Scripts\python.exe scripts\retrieve_regions.py search --index data\index_regions_products_v1 --image assets\query.jpg --strategy attention --output artifacts\my_region_image_001

# 用户选定局部，归一化坐标
.\.venv312\Scripts\python.exe scripts\retrieve_regions.py search --index data\index_regions_products_v1 --image assets\query.jpg --roi 0.2 0.2 0.8 0.8 --output artifacts\my_region_roi_001

# --attributes读取用户要求的JSON，例：{"图案":"纯色"}
.\.venv312\Scripts\python.exe scripts\retrieve_regions.py search --index data\index_regions_products_v1 --text "纯色服饰" --category "服饰穿搭" --attributes configs\retrieval_attributes_example.json --output artifacts\my_region_attributes_001

# 同款开发消融，使用新实验目录
.\.venv312\Scripts\python.exe scripts\benchmark_regions.py --output artifacts\module2_regions_benchmark_v2

# 已交付v1结果复核，不运行模型
.\.venv312\Scripts\python.exe scripts\verify_regions.py
```

七项缓存分项对照可执行 `scripts/analyze_region_views.py`，使用 `--output` 指定新目录。

输出目录内 `results.json` 保存结果与参数，`results.html` 可本地查看，图片查询另存查询裁切。索引清单覆盖向量、元数据、裁切及叠加预览的SHA256；模型revision或区域预处理变化时拒绝混用旧索引。CLI先停止本项目Ollama生成用千问，之后仅加载检索嵌入模型。

当前产品化入口为CLI与离线HTML，还未交付支持上传、拖框和即时查询的交互服务。模型冷启动与索引全量哈希校验可能使首次完整响应超过5秒；性能验收需要明确预加载服务与冷启动条件。

## 实验边界与下一轮

本轮复用26查询、334候选的服饰同款开发协议，先冻结协议和预设配置，再计算三种排序。保留所有查询的完整排序、向量、指标与变化案例。该集合此前已用于问题诊断，仍是开发集；与原PDF三大品类的广义相关商品任务不同。

后续围绕同一模块二推进：

1. 建立独立商品相关性数据，覆盖中文文搜图、整图搜商品、小目标、背景干扰、遮挡、局部细节以及无法匹配的查询；保留商品组隔离。
2. 当前缓存实验已比较ROI、中心、窗口与注意力，下一轮补上单独的放大消融；在开发集确定策略，在独立测试集报告最终收益与退化。
3. 复杂背景ROI不足时，评估无真值输入的检测／显著性候选，以检索收益决定是否加入。相关策略服务于检索，不扩展成模块三分割与问答交付。
4. 若需要学习型注意力，在商品组隔离的训练集上训练小型投影与区域门控，加入困难负例，再考虑对比学习或LoRA。训练权重与测试集分开，不能加入随机层就宣称有效。
5. 构建常驻模型的交互Demo，支持图片上传、用户ROI选择、查询条件、Top-N和匹配区域展示；测量完整响应P50/P95。
